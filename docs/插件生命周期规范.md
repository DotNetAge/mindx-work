# mindx-work 插件生命周期规范

- 状态：定稿 v1.0（2026-10-08）
- 权威性：本文是插件全生命周期的**单一权威规范**——身份与版本模型、发布包格式、manifest 契约、校验分层、安装目录、运行期加载、生命周期操作语义、信任边界、市场分发、开发与打包。实现与本文冲突时，以实现Bug论；修订本文须经用户确认。
- 读者：壳内核维护者、插件开发者、mx-plugin-dev 技能（`mx-plugin-dev/references/contract.md` §18 为本规范的摘要视图，细节冲突时以本文为准）。
- 实现锚点：安装与代际 `electron/src/plugin-store.ts`；语义校验 `ui-shell/src/plugin-manifest.ts`；协议与 IPC `electron/src/plugins.ts`；渲染加载器 `app/src/loader.ts`；mw CLI `electron/src/cli.ts`。

## 1. 术语与两类插件

| 类别 | 来源 | 形态 | 可删除性 |
| --- | --- | --- | --- |
| 内置（core） | `plugins/src/<name>/` 编译进壳 | TS 模块，命名导出 `VuePlugin`，可用工程内依赖 | 不可（随应用发版） |
| 在线（market） | .mindpkg 安装落盘 | 独立 ESM（`.mjs`），default 导出，无 npm import 通道 | 可（卸载/启停/切版） |

两类插件的运行契约**完全一致**（八区注册 API、样式军规、id 前缀、清理函数），唯一差异是可删除性。机制零分叉是硬约束：给 market 插件开的口子必须同时对 core 成立，反之亦然。

**官方可选件**不是第三种运行形态——它是 market 形态的官方分发通道变体：官方开发、源码托管在 `mindx-work/.agents/plugins/`、构建物随发行版搭载、用户选择式释放安装（详见 §11.1）；运行期与市场安装的插件完全一致，可卸载、卸载后可重装。

## 2. 身份与版本模型

- **id 是身份**：反向域小写 id（至少两段，如 `com.example.viewer`），安装后不变；安装目录、协议 host、安装清单主键都由它派生。格式：`/^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*)+$/`。
- **version 是不可变代际**：严格三段 semver（`/^\d+\.\d+\.\d+$/`，不含通配与范围）。同版本重装允许覆盖程序资源；版本一旦发布到市场即字节绑定（服务端 `duplicate_version` 409 兜底）。
- **activeVersion 是激活指针**：保存在安装清单；更新 = 落新代际目录 + 指针迁移；**回滚 = 切回旧指针**（旧代际原样保留）；只有卸载才删除全部版本目录。
- **fingerprint**：`sha256(canonical({author,id,version}))` 64 位十六进制，版本代际身份标识。格式校验在 `manifestIssues`；**重算校验唯一家在服务端发布管线**（防冒名与篡改）。存量包可缺失（兼容），新发布必带。

## 3. 发布包格式（.mindpkg）

zip 包，包根必须含 `manifest.json`；内容 = manifest + entry（`.mjs`）+ 静态资源。资源后缀白名单（协议层）：`.mjs / .json / .css / .svg / .png`。

体积与数量上限（防解压炸弹）：包体 ≤ 50MB、解压总量 ≤ 100MB、文件数 ≤ 2000（`plugin-store.ts` 常量，安装管线双预检：content-length 与解压后实算）。

包完整性 = 包文件整体 sha256（安装清单随代际记录；市场安装时与货架下发的 `sha256` 比对，不符即拒装）。

## 4. manifest 契约全文

| 字段 | 类型 | 必填 | 校验 | 用途 |
| --- | --- | --- | --- | --- |
| id | string | 是 | 反向域正则（§2） | 身份；目录/协议/清单主键 |
| name | string | 是 | 非空白 | 展示名 |
| version | string | 是 | 三段 semver | 代际 |
| description | string | 是 | 非空白 | 市场卡片与安装确认正文 |
| author | string | 是 | 非空白 | 署名（社区分发信任基础） |
| url | string | 否 | http(s) URL | 插件主页 |
| repo | string | 否 | http(s) URL | 源码库（卡片展示） |
| license | string | 是 | 非空白（SPDX） | 许可证 |
| entry | string | 是 | `.mjs` 后缀且包内存在 | 入口文件 |
| permissions | string[] | 是 | 字符串数组 | 权限**告知**（安装确认展示，不构成授权） |
| mxApiVersion | string | 是 | 等于壳 `MX_API_VERSION`（当前 `'1'`） | 契约版本；不匹配即拒绝加载（未知版本明确拒绝，不猜测兼容） |
| fingerprint | string | 否（新发布必带） | 64 位 hex | 代际身份指纹 |

## 5. 校验分层（同进程信 TS，边界才校验；两层各自完整不互代）

| 层 | 位置 | 职责 | 时机 |
| --- | --- | --- | --- |
| 机械校验 | 主进程 `plugin-store.ts` | 防路径穿越（id/version 格式、entry 存在、包内路径与入口路径不越界根）、体积/数量上限、sha256 | 安装落盘前 |
| 语义校验 | 渲染侧 `ui-shell/src/plugin-manifest.ts` `manifestIssues()` | §4 全字段（唯一家）；一次收集全部问题 | 加载激活前；打包工具必须复用同一函数 |
| 指纹重算 | mindx-market 服务端发布管线 | canonical 三元组重算比对 | 发布时 |
| 激活期复调 | `validateShellConstraints(app)` | 壳硬约束（order 保留段等）；违规 = 清理回滚 + 激活失败 | 入口执行后 |

## 6. 安装目录与清单

- 安装根：`app.getPath('userData')/plugins`（macOS = `~/Library/Application Support/MindX Work/plugins/`，由 productName 决定，勿改）；mw CLI 按平台同构推导，`MW_PLUGIN_ROOT` env 可覆盖（多实例/验收隔离）。
- 布局：`<root>/<id>/<version>/…`（两层缺一不可——一层装不下多代际并存）；状态文件 `<root>/installed.json`。
- `installed.json`：`{ schemaVersion: 1, plugins: [{ id, name, enabled, activeVersion, origin?, versions: [{ version, sha256, installedAt, publishedAt? }] }] }`。`origin` 为安装来源（`market` 市场货架 = 缺省可省；`core-optional` = 官方可选件释放）。纪律：`schemaVersion` 未知即拒绝读取（不猜测兼容）；**只增字段**；原子写（同目录临时文件 + rename）；损坏恢复 = 备份现场后按空清单继续（用户可重装，代际纪律不适用于已损坏文件）。
- `installed.json` 是状态文件受上述纪律约束；版本目录属程序资源，同版本重装允许覆盖。

## 7. 运行期加载与激活

- 通道：特权协议 `mx-plugin://<id>/<version>/<file>`（host = id，路径首段 = version，与安装目录同构；dev 与产物统一，无环境分叉）。`registerSchemesAsPrivileged` 必须在 app.ready 前调用（app.ready 后静默无效——实踩）。协议 handler 机械校验后经 `net.fetch(pathToFileURL())` 回读。
- 激活序列（`app/src/loader.ts`）：fetch `mx-plugin://<id>/<version>/manifest.json` → `manifestIssues` 全量校验 → 目录身份一致性（`manifest.id === view.id`）→ `import(/* @vite-ignore */ <base>/<entry>?activate=<递增序号>)` → `mod.default(app, { h, MxIcon })` → `validateShellConstraints` 激活期复调 → 持有清理函数。
- 入口签名（与 core 插件同一契约，多一个渲染工具包参数）：

```ts
export default function (app: AppShell<unknown>, mx: { h: typeof h; MxIcon: typeof MxIcon }): void | (() => void)
```

- **无 npm import 通道**：动态插件从特权协议加载，禁止 import 任何工程内模块；渲染工具（`h` / `MxIcon`）由壳注入。
- **ES module 缓存穿透**：同一 specifier 只求值一次——停用再启用、切版往返、卸载重装都必须给 import URL 加唯一 query（`?activate=<seq>`）重新执行入口；协议按 pathname 解析，query 安全。
- 启停/切版/卸载先行 `deactivate`（清理函数执行；清理失败记录后继续，坏插件不得卡死壳）。activate 幂等 + in-flight 并发防护（复用在飞 Promise 防双跑）。**激活中的插件重新 activate 幂等返回**——装新代际前必须先显式 deactivate，否则继续跑旧代际（实证坑）。
- 失败隔离：单插件激活失败收集为失败清单以 banner 呈现，不挡首帧、不阻塞其余插件；纯 Web 环境（无 `window.mxDesktop`）无 market 机制。
- order 纪律：在线插件注册条目 order 一律 ≥ 1001（1–1000 为壳内置与预置插件保留段）。
- 运行期启停不切页：停用移除活动条目时 Content 回退 order 最小条目；重新激活不自动跳转（activeId 由 Sidebar 行点击唯一写）。

## 8. 生命周期操作语义

所有操作的入口：设置 → 插件页（UI）、mw CLI（终端/Agent）、市场货架（安装）。三者是**同一安装管线的三个薄壳**，语义一致性由 `plugin-store.ts` 保证。

| 操作 | 语义 | 即时生效链 |
| --- | --- | --- |
| 安装 | 市场下载（URL + 期望 sha256 + publishedAt）、本地导入（文件对话框 / CLI 传路径）、官方可选件释放（§11.1，origin=core-optional）三来源之一 → 机械校验 → 落盘为代际 → 指针指向新代际 → 登记 | 原子写清单 → 主进程 watch 安装根目录（防抖 300ms，**watch 目录而非文件**——rename 使文件句柄失效）→ 广播 `plugins:changed` → 渲染差分激活 |
| 启停 | `installed.json` enabled 翻转；停用执行清理函数 | 同上；停用先 deactivate 再广播 |
| 切版 | activeVersion 指针迁移（仅限已装代际）；先停旧代际再激活新代际 | 同上 |
| 卸载 | 删除该 id 全部版本目录 + 清单移除；先 deactivate | 同上 |
| 导出 | 激活代际目录重打包为 zip（与安装包同格式，可重装） | 无 |
| 更新 | = 安装同 id 更高版本（货架对"有未装新版本"的插件保持可装，文案区分） | 同安装 |

CLI 即时生效的关键：主进程 watch 的是**目录**；CLI 与 app 是不同进程，靠文件系统事件 + `plugins:changed` 广播汇合。`mw plugin list --json` 供 Agent 机器可读确认落盘状态。

## 9. 信任模型与安全边界

- **显式安装即信任**（对齐"面板手势免审批"分级）：安装确认 UI 必须完整呈现 author / url / repo / license / permissions / version；放弃 node:vm 沙箱——桌面端安装即本机手势，market 插件与 core 同权。permissions 仅告知。
- **SSRF 防线**（市场下载）：禁自动重定向、逐跳断言目标为公网（IP 字面量直判 + 域名全地址解析逐个判定，私网/回环/CGNAT/链路本地全拒）、总超时 30s、content-length 与实量双检。
- **信任开关**：`MX_MARKET_DEV` env 显式置值 = 开发者/私有部署本机手势（本地验收指向 `127.0.0.1` 市场源合法），该模式下源与包地址全部可信；生产 env 缺省强制公网。
- 路径安全三关：id/version 正则（拼路径前）、resolve 后必须仍在根/版本目录内（清单被篡改也拼不出越界协议路径）、包内解压路径逐文件校验。

## 10. 市场分发（kind=plugin）

- 服务端 kind 集：`agent | skill | plugin | team`；plugin 包经同一发布管线（内容寻址落盘 / sha256 / 内容扫描 / 审计 / 幂等），`fingerprint` 由服务端重算校验。
- 货架：客户端 `market.list kind=plugin` 分页拉取；包条目 `download_url` + `sha256` 直连安装管线；安装前先 `deactivate`（§7 实证坑）。
- 发布格式对齐 mindx-market 发布纪律：**发布源目录必须只含待发布包**（包身份按 manifest 的 kind/name 推导，混入旧包会污染版本历史）；版本三选一（包内 manifest version > 参数 > 时间戳）；发布后必须 `curl /manifest` 核对 sha256 并下载一个包核对内容。
- 本地验收：`MX_MARKET_DEV=1` + 本地市场服务端（`mindx-market` 仓库 `make server`，默认 `127.0.0.1:8090`，含 plugin 货架数据）；真机验收四步循环与 CDP 判据见 mx-plugin-dev 技能 SKILL.md 验证节。

## 11. 开发与打包

| 形态 | 开发路径 | 产物 | 打包 |
| --- | --- | --- | --- |
| 内置（core） | mx-plugin-dev 技能（`plugins/src/<name>/` + scaffold + 三处注册） | 编译进壳 | 无需 |
| 在线（market） | 独立项目（`manifest.json` + `entry.mjs` + 静态资源；无 npm 工程内依赖，构建产物为单 .mjs 或自包含多文件）；**权威源目录 = 项目 `.agents/plugins/<id>/`**（用户未指定开发目录时 LLM 开发的插件源码一律放这，脚手架 `--market` 模式缺省也落这） | .mindpkg | `mw plugin pack <dir>`（机械 + 语义全量自检后产出 `<id>-<version>.mindpkg`） |
| 官方可选件 | 官方开发的 market 形态插件，源码一律 `mindx-work/.agents/plugins/<id>/`（TS/SFC 源码形态 + `plugin.json`） | .mindpkg（随发行版搭载） | `scripts/optional-plugins/build.mjs`（发行构建期自动扫描，见 §11.1） |

外部插件开发流程（闭环）：

```bash
# 1. 脚手架产出外部插件项目模板（独立目录，缺省落在项目 .agents/plugins/<id>/，不进 plugins/src）
python3 scaffold_plugin.py com.acme.widget --market "Acme"
# 2. 开发（入口 default export (app, mx) => cleanup；样式走注入的 MxIcon + 原语类，禁止工程内 import）
# 3. 打包（自检：manifestIssues 全量 + 机械校验 + fingerprint 重算）
mw plugin pack ./com.acme.widget        # → com.acme.widget-1.0.0.mindpkg
# 4. 本地直装验收（或经市场发布后从货架安装）
mw plugin install ./com.acme.widget-1.0.0.mindpkg
mw plugin list --json
# 5. 发布到市场（mindx-market 发布纪律见 §10）
```

### 11.1 官方可选件（发行搭载与选择式释放安装）

官方可选件是「随发行版搭载、用户选择式释放安装」的本地安装通道——不走市场货架，其余语义与市场安装完全一致（同一 `installZipData` 管线，origin=`core-optional`；卸载后可重装）。

- **权威源目录**：`mindx-work/.agents/plugins/<id>/`。官方可选件（gitgraph / video-editor / svgboard…）与 LLM 开发的外部插件源码统一放这——官方源码与用户运行期环境完全同构。可选件持续增多时**零脚本改动**（构建期扫描目录）。
- **源码形态**：TS/SFC 源码（可用工程内 Vue/Pinia/Element Plus 写法）+ `plugin.json`（字段与 §4 manifest 契约一致，另加 `export` 字段 = 源码命名导出函数名，构建 wrapper 用）。
- **构建桥**（`scripts/optional-plugins/build.mjs`，`pnpm build` 后由 `scripts/pack.mjs` 自动执行）：逐目录 vite 构建（`preserveEntrySignatures: 'strict'` 防 tree-shake 剥除入口导出；wrapper `.mw-wrapper.mjs` 静态转接 default）→ 产出 `entry.mjs` + manifest（含 fingerprint 补算，规则同 §2）→ 自检（fflate 回读）→ zipSync 为 `.mindpkg` 落 `dist-optional/`。工程内依赖禁止内联：vue / pinia / element-plus / ui-shell-vue 由生成式 shim 转接壳运行期桥 `window.__MINDX_BRIDGE__`——动态模块与壳共享同一 Vue/Pinia 实例（防响应式断裂）。
- **搭载**：electron-builder extraResources 将 `dist-optional/` 打进发行包 `<resources>/plugins-optional/`；目录为空时构建脚本自身跳过、extraResources 项不生效，无空目录残留。
- **释放安装**：主进程 `plugins:optional-list`（枚举搭载 .mindpkg，installed 标注）与 `plugins:optional-install`（file 名白名单防路径穿越）。释放入口两处：首启向导「安装」步（就绪后勾选列表，默认全选、可取消；单个失败不阻断主流程）与设置插件页「官方可选件」区（随时可装）。安装即走 §8 安装语义（watch 广播 → 差分激活）。

## 12. 文档权威性与变更纪律

- 本文修订 = 用户确认的契约变更；`MX_API_VERSION` 递增的触发条件是**破坏性**契约变更（删字段/改语义/收紧校验），只增可选字段不递增。
- `mx-plugin-dev` 技能 `references/contract.md` §18 是摘要视图：允许引用本文结论，禁止复制细节造成双源漂移（§18.6/§18.8 曾因静态清单时代未同步产生漂移——本规范落地后以本文为唯一事实）。
- 两份技能副本（`mindx/runtime/skills/`、`mindx-work/.agents/skills/`）内容必须一致；修订同步进行。
